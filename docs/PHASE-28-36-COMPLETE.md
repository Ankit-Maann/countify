# Countify v4.0.0 — Phases 28–36

## Phase 28 — AI Creator 2.0
Natural-language creator architecture remains available through the AI Creator route. Provider credentials must be supplied server-side; no model API secret belongs in the Vite client.

## Phase 29 — Theme Marketplace
Marketplace route and creator-theme schema are included. Paid theme fulfillment is tied to the same trusted billing boundary as subscriptions.

## Phase 30 — Growth Engine
Social Studio, QR/share tooling and public creator/discovery routes remain available. Growth analytics are bounded and privacy-friendly.

## Phase 31 — Real Billing
`/billing` is production-oriented: the browser requests a secure checkout URL from `VITE_BILLING_CHECKOUT_URL`. Stripe/Razorpay secrets, signatures and webhooks must live in the trusted server/Supabase Edge Function. No fake payment success is generated by the client.

Required production environment:
- `VITE_BILLING_CHECKOUT_URL`
- `VITE_BILLING_PORTAL_URL` (optional)
- `VITE_APP_URL` (server-side use recommended)

Recommended server flow: authenticate user → validate plan → create provider Checkout Session/Order → return hosted URL → provider webhook verifies signature → upsert `subscriptions` → grant entitlements server-side.

## Phase 32 — Teams / Business
Workspace, members, roles and brand-kit database structures are included, plus a Business product surface.

## Phase 33 — Embeds
`/embed` generates a lazy responsive iframe snippet. Public countdown routes remain the source of truth.

## Phase 34 — Security 2.0
RLS tables, server-side billing boundary, bounded analytics and security headers are included. Never place provider secrets in `.env` values prefixed with `VITE_`.

## Phase 35 — Advanced Analytics
Analytics dashboard surface plus schema for embed events and creator earnings. Production reporting should aggregate on the server and enforce retention/privacy rules.

## Phase 36 — Creator Economy
Creator earnings and theme-purchase schema are included. Payout/KYC/tax workflows must be implemented by a trusted payout provider/backend before real money is released.

## Navigation UX
Every platform route using `PlatformNav` now exposes **Back** and **Home**. The home screen exposes an **All Features** hub so discovery is not hidden behind Pro.

## Important billing truth
The frontend cannot safely contain Stripe/Razorpay secret keys. Therefore the supplied app contains the complete client boundary and database schema, but provider credentials and webhook verification must be configured in a trusted backend/edge function. This is intentional production security, not a missing fake checkout.
